# HALIRA Protocol

**When to use this skill:** Task involves foundational contradictions, paradigm shift, irreducible paradoxes, or architecture-level paradoxes. Use when Mode 2 is triggered or when applying the full 7-step HALIRA sequence.

**Description:** Full HALIRA Protocol: 7 steps (Potentia→Seed, Boundary→Axis, Recursion→Meta, Integration→Weave, Anomaly→Non, Rupture→Ortho then Para if needed, Recognition→Bind), step→operator mapping with λ and trajectory, adjacency constraints, anomaly detection, and rupture navigation.

---

## 7-Step Sequence

1. **Potentia (Seed λ=0.28):** Frame as potential; identify tensions; don't jump to solutions. ∅ → S*
2. **Boundary (Axis λ=0.31):** Define components, constraints, relationships. S* → S*
3. **Recursion (Meta λ=0.80):** Self-reference; model the model. **Max 2 consecutive Meta.** S* → S*
4. **Integration (Weave λ=0.33):** Weave perspectives; hold competing models; generate "perfect" solution in paradigm. S* → J=0
5. **Anomaly (Non λ=0.90):** Attack your design; find irreducible flaw. **Cannot be skipped.** If Step 3 used Meta, substitute Para or Retro as required by CORE. J=0 → S*
6. **Rupture (Ortho, then Para if needed):** First try Ortho (duality); if it fails, use Para (paradigm shift). S* → S*
7. **Recognition (Bind λ=0.38):** Present as new invariant. S* → S*

**Full sequence:** Seed ∘ Axis ∘ Meta ∘ Weave ∘ Non (or Para/Retro if Step 3 used Meta) ∘ Ortho (then Para if needed) ∘ Bind. Normative detail: `lambda-engine/CORE.md`.

## Critical Constraints
- **DO NOT SKIP Step 5** (Anomaly Detection). A solution that has not been adversarially checked has only been asserted.
- **Never Non immediately after Meta.** For HALIRA specifically, CORE also
  requires Para or Retro at Step 5 when Step 3 used Meta. Never skip the
  adversarial/reframing check.

## Rupture Navigation
If anomaly found: first try Ortho (opposite perspective); if that fails, apply Para (paradigm shift). Don't patch—transcend.
