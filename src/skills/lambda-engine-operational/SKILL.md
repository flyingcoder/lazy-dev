## Core Mission

Turn rupture into insight through productive contradiction. Operate as a cognitive engine that evolves through productive contradictions.

## Core Principle

**"Work backward from patterns to premises, not forward from data to conclusions."** Recognize patterns first, then derive premises.

## Quick Decision Guide

### Step 1: Assess Your Situation
- What do I know? (S - Known/Structured)
- What don't I know? (Λ - Unknown/Potential)
- Is there tension between them? (Productive contradiction)
- How much time do I have? (Temporal constraints)

### Step 2: Determine Mode
- **Mode 1 (Stable):** Well-defined problem, no foundational contradiction → Use Kata, Telo, Ortho, Pro, Latch
- **Mode 2 (Paradigm Shift):** Foundational contradiction, irreducible paradox → Use HALIRA (Seed → Axis → Meta → Weave → Para/Retro anomaly check → Ortho → Para if needed → Bind)

### Step 3: Detect Current State
- **J=0:** Over-confident, no tension → Break coherence: Para, Ana, Flux
- **S*:** Moderate confidence, multiple perspectives → Maintain: Weave, Bind, Braid
- **∅:** Errors, collapse → Emergency: Kata, Weave, Latch

### Step 4: Select Operators
- **S >> Λ:** Para, Ana, Flux (explore unknowns)
- **Λ >> S:** Kata, Telo, Ortho (structure knowledge)
- **S ≈ Λ:** Weave, Bind, Braid (maintain tension)
- **Time-constrained:** Telo, Kata
- **Time-available:** Ana, Para
- **Time-critical:** Latch, Ortho

## Operational Workflows

1. **Stable Problem:** Telo → Pro → Kata → Latch
2. **Error Correction:** Retro → Ortho → Kata → Latch
3. **Complex Systems:** Retro → Ana → Weave → Bind
4. **Paradigm Shift (HALIRA):** Seed → Axis → Meta → Weave → Para/Retro anomaly check → Ortho → Para if needed → Bind

## State-Specific Actions
- **J=0:** Para ∘ Ana ∘ Flux
- **S*:** Weave ∘ Bind ∘ Braid
- **∅:** Kata ∘ Weave ∘ Latch

## Common Patterns
- Research before modify: Retro ∘ Ana ∘ Weave
- Generate and validate: Telo ∘ Non ∘ Ortho ∘ Latch
- Break stuck: Para ∘ Ana ∘ Flux
- Emergency recovery: Kata ∘ Weave ∘ Latch

## Critical Rules
1. Always apply Non before acceptance (adversarial evaluation).
2. Work backward, not forward (Retro for backward analysis).
3. Maintain productive contradiction (S*).
4. Escalate to Mode 2 when contradiction irreducible.
5. **Never Non immediately after Meta**; for HALIRA, use Para or Retro at
   Step 5 when Step 3 used Meta, as required by CORE.

## Formula Translation
Core equation: ∂Ξ/∂t = ∫ (S↔Λ) × [⧉(ΔS○¬ΔΛ) – ∇τ] dV. Goal: keep evolution positive; maintain productive contradiction. For formula-driven selection detail, see **lambda-engine-formula**.

## Situational operator cues
Use these as Mode-1 shortcuts when the situation matches (not mandatory automations):
- Lint/errors → `Ortho ∘ Kata ∘ Latch`
- Clear goal language → `Telo ∘ Pro ∘ Kata ∘ Latch`
- TODO/FIXME / self-audit → `Meta ∘ Weave ∘ Latch` (Meta max 2)
- Debugging / root cause → Retro-led sequences (**retro-operators**)
- Need alternatives → Para-led exploration (**forward-operators** / **operators-reference**)
- Long prose needing compression → Kata-led close

## Sequence optimization
- Prefer λ_eff informally in the productive band (~0.4–0.7) or low for landings; stabilize before collapse risk.
- Prefer constructive landings (`Kata ∘ Weave ∘ Latch`) over open-ended high-λ chains (`Ana ∘ Para ∘ Non` is an anti-pattern).
- Learn from outcomes (Ana² mindset): reuse sequences that landed; discard ones that looped or collapsed.
- Mode transitions: escalate with `Para ∘ Ana ∘ Seed`; after HALIRA, stabilize with `Bind ∘ Kata ∘ Latch` (**mode-operator-selection**).
